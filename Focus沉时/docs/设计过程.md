# Focus 沉时｜最终版设计过程

## 版本演进

1. **基础闭环**：先完成任务、计时、记录及 SQLite 存储，验证“设定任务—专注—保存—回顾”。
2. **多人能力**：增加用户账号、按用户隔离的资料、邀请码教室、成员状态与今日排名。
3. **产品体验**：将名称统一为 Focus 沉时，引入学习伙伴“小时”；页面改为协调的奶油黄卡通风，独立设置许愿墙、白噪音和重要日期。
4. **业务细化**：增加正/倒计时、本次时长、任务累计达标自动完成、日/近七天/月统计、早起/日常打卡与手记历史。
5. **课堂交付**：构建 H5 页面，保留后端源码、测试、运行脚本和截图；分离公开仓库材料与本机演示数据。

## 架构与数据

浏览器加载 `miniapp/dist/build/h5/`；前端源码位于 `miniapp/src/`，采用 Vue 3 / uni-app。`server/` 使用 Node.js 提供同源网页、JSON 接口、鉴权、业务校验和音频服务。SQLite 数据库在本地 `data/` 目录，核心表包括用户/令牌、任务、专注记录及片段、教室与成员、打卡、手记、倒计时和愿望。前端请求后端接口，后端按登录用户查询私人数据；教室与愿望只按明确的共享规则返回。

账号密码采用带随机盐的 scrypt 哈希；登录令牌在数据库中保存摘要。数据库和密钥不进公开仓库。一个账号最多有一条活动专注；暂停时间不计入专注，放弃不会成为完成记录；任务只累计完成的关联专注，达标后自动完成。统计按北京时间自然日拆分专注片段，近七天图覆盖连续七日。早起打卡由用户设置的当日截止时间判定。教室成员状态与排名通过请求更新，并非 WebSocket 实时广播。

## 验证与边界

项目根目录运行 `node --test tests/*.test.mjs`，覆盖账号隔离、任务达标、计时、统计跨日、打卡、手记、自习室排名及愿望等场景。课堂应以实际运行网页为准；截图只是故障备用。当前共享自习室要求两位用户连接**同一个** Node.js 后端。网页已构建可直接运行；微信小程序正式发布、公网容量测试不作为本次成果陈述。
